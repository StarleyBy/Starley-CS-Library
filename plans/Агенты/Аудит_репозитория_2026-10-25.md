## 1. Срочное: токен Telegram-бота в публичном коде

- **Где:** `assets/js/quiz.js`, строка 2474 (константа `TELEGRAM_BOT_TOKEN`), там же прописан идентификатор чата администратора. Токен используется функцией `sendTelegramAdminReport` (кнопка «сообщить о проблеме») для прямых запросов к `api.telegram.org` из браузера.
- **Почему это серьёзно:** файл раздаётся сайтом GitHub Pages, а репозиторий публичный; токен присутствует в 5 коммитах истории. Любой посетитель может прочитать токен и отправлять сообщения от имени бота (в том числе вам), читать входящие сообщения бота через `getUpdates`. Очистка истории git ничего не отменит: токен уже опубликован.
- **Что сделать (по порядку):**
  1. Отозвать токен: в Telegram, @BotFather → `/revoke` → выбрать бота → получить новый токен. Пока токен не отозван, считайте его скомпрометированным.
  2. Хранить новый токен только на сервере: секрет Supabase Edge Function (как уже сделано для `admin-create-user`) или секрет GitHub Actions.
  3. Заменить прямые вызовы Telegram из браузера обращением к серверной функции (это задача «Кодера» и будущего «Supabase-инженера» по вашему решению). Серверная функция должна проверять вызывающего (например, требовать авторизованного пользователя Supabase) и ограничивать частоту, иначе спамить можно будет через неё.
  4. Пока серверной функции нет, после отзыва токена кнопка «сообщить о проблеме» перестанет доставлять сообщения: это неизбежная плата за безопасность. Решите, в каком порядке действовать.
  5. Чистка истории (`git filter-repo` и `push --force`) — по отдельной просьбе и только после отзыва; она не обязательна, если токен отозван.
- **Проверка:** после замены `node tools/check-repo-health.mjs` не должен выдавать G005.
