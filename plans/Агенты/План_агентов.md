Версия плана: 1.0 · Дата: 23.10.2026 · Основа: разбор репозитория `StarleyBy/Starley-CS-Library` (ветка `main`, 65 коммитов)

## 0. Кратко

1. Сейчас в проекте три рабочих агента (`editor`, `guideliner`, `coder`) в `.agents/skills/`. Они сильные, но стоят на «голой» земле: нет общего входного файла для агентов, нет проверяющих агентов (валидаторов), нет агентов для квиза, таксономии, кэша PWA, медиа и репозитория — а именно там сейчас идёт основная работа.
2. Предлагается **два слоя**:
   - **Глобальные агенты (G)** — отвечают на вопрос «КАК работать»: универсальные, без путей и терминов вашего приложения. Подходят любому проекту (CS Helper, Wolfson Schedule, RPG-платформа и т. д.).
   - **Локальные агенты (L)** — отвечают на вопрос «ЧТО и ГДЕ в Starley»: знают структуру `books/`, `data/guidelines/`, `quiz/`, `sw.js`, формат `<details class="med-details">` и т. д.
   - Связка между слоями — файл **`AGENTS.md`** в корне: там «где лежат команды проверки, какие пути, какие правила». Глобальный агент читает его и подстраивается под проект.
3. Всего в каталоге: **34 глобальных** и **34 локальных** агента (включая 3 существующих), у каждого приоритет P0–P3. Внедрять предлагается волнами (раздел 8): сначала фундамент и P0, остальное — по мере нужды.
4. Отдельно (раздел 5) — конкретные правки в три существующих навыка: найдено несколько противоречий и пробелов.

### 1.3 Найденные пробелы и противоречия

1. **Нет единого входа для агентов.** Нет `AGENTS.md` в корне: каждый агент заново «узнаёт» проект. Общие правила (язык отчёта, запрет трогать `.env`, git-дисциплина) повторяются или отсутствуют.
2. **Несколько источников правды.** Инструкции живут и в `plans/…`, и в `.agents/skills/…`, плюс `Master_prompt.md`. Через месяц они разойдутся.
3. **Нет проверяющих агентов.** Есть те, кто создаёт (Редактор, Гайдлайнер), нет тех, кто независимо проверяет: структуру глав, клинические числа, соответствие `metadata.json` файлам, перевод EN↔RU.
4. **Квиз и таксономия без агента**, хотя это сейчас самая активная зона (редизайн квиза, таксономия 36 → 142 → ~3 887 тегов, привязка глав к таксономии, `book-taxonomy-map.json`).
5. **Непоследовательность эмодзи в манифестах.** Редактор запрещает эмодзи в документах, но пример записи в `metadata.json` содержал `📚`. Проверка показала: в `cohn/metadata.json` 63 названия глав с этим маркером, а в `Kirklin5` и `bojar` — ни одного. То есть в проекте два формата. В навыке теперь правило «следуй конвенции соседних записей книги»; единый формат — решение владельца (раздел 9).
6. **Гайдлайнер знает только ESC и AHA/ACC.** В `data/guidelines/` уже есть `eacts-periop-2024` и `eacts-tmcs-2026` — правил для EACTS/STS в навыке нет (легенда, префиксы, классы).
7. **Гайдлайнер «приступает без расспросов»**, но при чтении скриншотов неизбежна неоднозначность (мелкий шрифт, цвет ячейки, сноска). Нужен режим «двойной проход + список сомнений», иначе ошибки попадают в клинические данные молча.
8. **Кодер привязан к конкретной среде:** имена инструментов (`grep_search`, `view_file`, `replace_file_content`) и PowerShell-команды. При смене среды навык частично «сломается». Нужна нейтральная формулировка.
9. **Монолит `quiz.js` на 10 754 строк** — агенту нужны правила чтения больших файлов (по диапазонам, по карте функций), иначе он будет «терять» контекст и ломать соседний код.
10. **Мусор и дубли в корне:** `debug_ch1.js`, `extract_summaries.js`, `extract_multiple_summaries.js`, `image-stats.js`, папка `scratch/` (десятки `build_block*.py`), `combain/` (опечатка), два файла `nojekyll`/`.nojekyll`, `assets/css/reader.css.backup`, `quiz/inv_before.txt`, `plans/task1.md` (82 КБ).
11. **Хвосты LFS.** В `jekyll-gh-pages.yml` стоит `lfs: true` с комментарием «пока в репо есть LFS-указатели», а `.gitattributes` пуст и `git lfs ls-files` ничего не показывает. Скорее всего, флаг уже не нужен — после недавнего кризиса с квотой стоит убрать лишнее (проверьте сами перед удалением).
12. **Pre-commit хук синхронизирует R2 при каждом коммите** — без сети коммит блокируется. Нужны явные правила для агентов: когда запускать, что делать при ошибке, как не потерять работу.
13. **Репозиторий публичный**, а в нём полные тексты глав коммерческих учебников. Это вопрос не к агентам, а к вам — но агент «Хранитель лицензий» (G30) должен хотя бы вести реестр источников и статус прав. См. раздел 9.

## 2. Архитектура: как устроены слои

### 2.1 Принцип «КАК» (глобальные) и «ГДЕ» (локальные)

- **Глобальный навык** не содержит ни одного пути Starley. Вместо `node tools/validate-tables.mjs` он пишет «выполни команду проверки из раздела *Project commands* в `AGENTS.md`».
- **Локальный навык** наследует глобальный (`inherits: G05`) и добавляет только специфику: пути, форматы, словари, команды, запреты.
- **`AGENTS.md`** — единственная «карта проекта»: структура, команды, жёсткие правила, реестр агентов, контракты передачи работы.

### 2.2 Предлагаемая структура

```text
AGENTS.md                      # общий вход (Antigravity читает его напрямую; GEMINI.md нужен только для правил, специфичных для Antigravity)
.agents/
  skills/
    editor/  guideliner/  coder/          # существующие (будут обновлены)
    quiz-master/  taxonomist/  ...        # новые локальные (scope: local)
  REGISTRY.md                  # реестр: id, имя, scope, статус, версия, зависимости
plans/Агенты/                  # планы и архив старых инструкций (не источник правды)
tests/{unit,sandbox}/.gitkeep  # чтобы песочница реально существовала в git
tools/                         # проверочные скрипты, на которые опираются агенты (раздел 6)
```

**Глобальные навыки** хранить вне репозитория, чтобы они подключались ко всем проектам. Для Antigravity (среда владельца) по данным документации и руководств: навыки проекта — `<проект>/.agents/skills/<имя>/SKILL.md` (устаревший путь `.agent/skills` тоже читается), глобальные — `~/.gemini/antigravity/skills/<имя>/`, при совпадении имён навык проекта главнее глобального; общий контекст — `AGENTS.md` в корне (читается и другими средами), `GEMINI.md` — только для переопределений, специфичных для Antigravity. Навык подгружается по `description` (всегда видны только имя и описание, тело — при совпадении задачи), поэтому триггерные фразы в описании обязательны, а объёмные справочники выносятся в `references/`. Сведения взяты из сторонних руководств и документации; перед массовым переносом проверьте пути в актуальной документации Antigravity.

### 2.3 Единый шаблон SKILL.md

```markdown
---
name: <slug>
description: <одно предложение: что делает + триггерные фразы («Валидатор», «проверь главу»)>
scope: global | local
inherits: <id глобального агента, если local>
version: 1.0
priority: P0 | P1 | P2 | P3
depends-on: [агенты/инструменты, на которые опирается]
---

# Роль и миссия
# Границы (что агент НЕ делает и кому передаёт)
# Входы (что должен получить; что делать, если чего-то нет)
# Выходы (файлы, отчёт)
# Жёсткие правила
# Пайплайн (шаги, команды проверки)
# Самопроверка перед сдачей (чек-лист)
# Формат отчёта пользователю
# Когда остановиться и спросить
```

Пункт **«Границы»** и **«Когда остановиться и спросить»** сейчас отсутствуют во всех трёх навыках — это самые полезные добавки.

### 2.4 Скелет AGENTS.md (черновик)

```markdown
# AGENTS.md — Starley CS Library
## Что это
PWA-библиотека по кардиохирургии/реанимации (Vanilla JS/CSS, без фреймворков). Контент: books/, data/guidelines/, quiz/.
## Карта репозитория
(10–15 строк: путь → назначение)
## Project commands
- Проверка гайдлайнов: node tools/validate-tables.mjs
- Индекс таблиц: node tools/build-tables-index.mjs
- Поисковый индекс (тяжёлый, ~81 МБ — только в конце пакета правок): node search/generate-search-index.js
- Все тесты: node tests/run-all.mjs
- Локальный сервер: npm start (порт 8085)
## Жёсткие правила
1. Нулевая регрессия: правки точечные, комментарии не удалять.
2. Временные файлы — только tests/sandbox/.
3. Не читать/не коммитить .env и секреты; не добавлять зависимости без вопроса.
4. Деструктивные git-операции (reset --hard, force push, удаление веток) — только по прямому указанию.
5. Медицинский контент: EN — источник истины; ничего не выдумывать и не «улучшать» клинические данные; сомнение → в отчёт, не в данные.
6. Изменил клиентские файлы из APP_SHELL → проверить/поднять версию кэша в sw.js.
## Язык и отчёт
Отвечать по-русски; ссылки на изменённые файлы; что проверено и чем.
## Реестр агентов и передача работы
(таблица из REGISTRY.md + цепочки из раздела 7 этого плана)
```

### 7.2 Контракт передачи (что агент отдаёт следующему)
Каждый агент в конце отчёта выводит блок:

```text
ПЕРЕДАЧА
- Что изменено: <список файлов>
- Что проверено: <команды и результат>
- Сомнения/открытые вопросы: <список или «нет»>
- Следующий агент: <ID и зачем>
```

Это превращает цепочку из «агент сказал, что готово» в проверяемый процесс.
