Новая фича. Я хочу внедрить интерактивные таблицы из гайдлайнов, доступные для просмотра на главной странице, в режиме чтения, в режиме квиза. В каждой такой таблице должно быть указано гайдлайн (например, ECS Acute coronary syndrome 2023) + название самой таблицы + сама таблица, с различным фоном ячеек в зависимости от содержимого. Для чего это нужно: таких таблиц очень много, и иногда полезно иметь под рукой возможность буквально в 2-3 клика открыть нужную таблицу гайдлайна, чтобы проверить/подсмотреть данные, как в справочнике. Так вот, от тебя требуется методическое руководство: подробная инструкция по реализации. Не забывай про английскую и русскую версию. И, самое главное, каким образом такую таблицу из "картинки" перевести в наш интерактив? манифесты? И неплохо бы реализовать поиск по всем таблицам, а также добавить такой поиск в уже существующий поиск. Предусмотри добавление ремарки к таблице (к каждой таблице по некоторым пунктам и строкам есть пояснения, но мы не будем загромождать таблицу и помещать их в ячейку, а реализуем возможность при клике на строку/ячейку/всю таблицу ознакомиться с этими данными. Заранее предусмотри возможность быстрого редактирования данных в таблице (добавить возможность в редактор или редактор манифестов или свой редактор для гайдлайнов?)

1. Главная идея: хранить смысл, а не картинку и не цвета

Таблицы ESC устроены семантически. Цвет ячейки не произвольный, он полностью определяется значением (Class I → зелёный, IIa → жёлтый, III → красный; Level A/B/C → три оттенка бирюзового). Поэтому:

В данных хранятся значения class: "IIa", level: "B". Цвет выдаёт CSS по токенам. Это даёт тёмную тему, смену палитры одной правкой и отсутствие ручного «покраски».
Таблица делится на два типа:
recommendations: таблицы рекомендаций (как на обоих скринах). Секции-заголовки (серые строки) и строки с текстом, Class, Level, ссылками.
grid: произвольные таблицы (шкалы риска, дозы, критерии). Строки и ячейки со стилевым тегом (tone: "green|yellow|red|neutral").

Один рендерер и один редактор на оба типа. Сначала делаем recommendations, потому что это 80% ваших случаев.

Принципы:

Каждый текст это {en, ru}. en обязателен и является источником истины. Если ru пуст, показывается EN с маркером, а таблица попадает в список «требует перевода». Аббревиатуры (STEMI, PPCI, GRACE) не переводим: это снимает проблему смешанных подписей.
Заметки отдельным словарём notes с адресом target: table, row:r1, cell:r1.class. Строка таблицы остаётся чистой, а в строке лишь значок, если заметка есть. Одна заметка может ссылаться на несколько строк.
Ссылки (refs) хранить числами. Список литературы гайдлайна лежит в guideline.json (опционально); пока достаточно показывать номера.
Стабильные id (esc-acs-2023.rt04) нужны для deep link: #/tables/esc-acs-2023.rt04. Тогда «в 2–3 клика» превращается в одну закладку.
3. Как превратить картинку в манифест

Пайплайн из четырёх шагов, по аналогии с вашим quiz-manifest промптом:

Скриншот таблицы в максимальном разрешении (PDF → PNG 200–300 dpi). Цветные ячейки не обрезать.
LLM-распознавание в JSON. Картинку и промпт отправляете мне (или в любой vision-модели). Промпт-шаблон:
Преврати таблицу рекомендаций с изображения в JSON строго по схеме [вставить схему].
Правила:
- Class и Level бери из ячеек как есть (I, IIa, IIb, III / A, B, C). Цвета не переноси.
- Серые строки-заголовки → sections[].title. Не смешивай с рекомендациями.
- Маркированные списки внутри ячейки → bullets[], не склеивай в один абзац.
- Надстрочные числа (51,182) → refs[] числами; буквы (a, b) → footnotes, не в текст.
- Курсив/полужирный (например, "Recurrent") сохрани как **…** / *…*.
- Текст не перефразируй, переписывай дословно, исправляй только переносы строк.
- Русский перевод в поле ru делай отдельным проходом, аббревиатуры не переводи.
- Если символ неразборчив, поставь "[?]" и не угадывай.
Выдай только JSON.
Автоматическая валидация (скрипт validate-tables.mjs, JSON Schema + проверки): допустимые Class/Level; уникальность id; все notes[].target существуют; нет пустых en; сумма строк совпадает с числом строк на картинке (передайте это число в source.expectedRows).
Человеческая сверка в редакторе (раздел 6): картинка слева, отрендеренная таблица справа. Для медика это самый надёжный шаг, потому что ошибка в Class или Level здесь клинически значима. LLM можно доверять в структуре, но не слепо в значениях.

Вместо отдельного «манифеста картинки» держите оригинальный PNG только как временный файл для сверки (не в репозитории: вы уже пережили историю с LFS).

4. Интерфейс

Рендерер (общий компонент GuidelineTable):

Шапка: бейдж гайдлайна («ESC ACS 2023»), номер и название таблицы, действия (заметки, копировать, закладка, ссылка).
Тело: секция-заголовок (серая полоса) → строки. Колонки: текст | Class | Level. На телефоне Class/Level остаются справа узким столбцом, текст занимает остальное; без горизонтального скролла.
Цвета только через токены:
css
:root{
  --cls-I:#4caf7d; --cls-IIa:#f2c200; --cls-IIb:#f08c2e; --cls-III:#d9534f;
  --lvl-A:#1f7f95; --lvl-B:#5aa9bb; --lvl-C:#bcdde5;
}

Подберите контрастный цвет текста для каждого токена (на Level C нужен тёмный). Отдельно проверьте тёмную тему.

Тап по строке разворачивает заметку (если есть). Тап по ячейке Class или Level показывает расшифровку («Class I: рекомендовано / показано»). Кнопка «Заметки» в шапке открывает все заметки таблицы. Значок-точка показывает, где заметки есть.
Поиск по тексту внутри открытой таблицы с подсветкой.

Точки входа (все открывают один и тот же компонент, поэтому дублирования кода нет):

Главная: плитка/раздел «Guidelines tables»: список гайдлайнов → список таблиц, плюс строка поиска и недавно открытые.
Режим чтения: кнопка в радиальном меню «Tables» открывает таблицу в нижней панели (bottom sheet), чтобы не уходить из главы. Контекстная подсказка: по тегам текущей главы предлагать связанные таблицы.
Режим квиза: то же в виде кнопки рядом с калькулятором и рисованием. Панель не перекрывает вопрос. Если квиз идёт с таймером, открытие таблицы ставит таймер на паузу (иначе это штраф за справку).

Опционально позже: «режим самопроверки», когда колонки Class/Level скрыты и нужно угадать. Данные у вас уже есть, это почти бесплатно.

5. Поиск
Индекс генерируется скриптом build-tables-index.mjs в tables-index.json. В записи: id, гайдлайн, номер, заголовки EN/RU, теги, плюс плоский список строк {tableId, rowId, textEn, textRu, class, level}. При размере в сотни таблиц это единицы мегабайт, поэтому строки лучше вынести в отдельный tables-search.json, который грузится лениво при первом поиске.
Нормализация: нижний регистр, ё→е, снятие диакритики, токенизация. Отдельно поддержать аббревиатуры (поиск PPCI находит «primary percutaneous coronary intervention» через abbreviations гайдлайна). Если в таксономии появятся алиасы, подключите их сюда же.
Ранжирование: совпадение в названии таблицы > тег > текст строки; точная фраза > отдельные слова. Для fuzzy достаточно Fuse.js или MiniSearch (они хорошо ложатся на статику).
Фильтры: гайдлайн, Class (например, «все III, то есть что не делать»), Level. Это очень полезно клинически.
Интеграция в существующий поиск: новый тип результата «Table» со своей иконкой. Клик открывает таблицу и прокручивает к строке с подсветкой (#/tables/id?row=r5). Не меняйте логику старого поиска, просто добавьте в него ещё один провайдер результатов.
6. Редактор

Я рекомендую отдельный редактор таблиц, а не расширение редактора глав или манифестов. Структура у данных другая (форма, а не текст), но инфраструктуру сохранения берите готовую: GitHub API save, токен, обработку конфликтов.

Что в нём должно быть:

Список слева, форма справа. Редактирование строки: поля EN/RU, выпадающие списки Class и Level (только допустимые значения), список bullets (добавить/удалить/перетащить), refs, привязка заметки. Добавление строк и секций, перестановка перетаскиванием.
Живое превью тем же рендерером.
Режим сверки: загрузить PNG локально (не в репозиторий) и показать рядом с превью.
Вкладка «Raw JSON» для массовых правок и вставки вывода LLM. Здесь же кнопка «Импорт из LLM»: вставили JSON, прошла валидация, ошибки подсвечены по путям.
Панель переводов: фильтр «нет RU», кнопка «перевести пустые» через ваш промпт.
Валидация перед сохранением (та же схема, что в скрипте) и diff перед коммитом. После сохранения автоматически пересобирается tables-index.json (GitHub Action или локальный скрипт).

8. Подводные камни
Автораспознавание цифр и классов. Ошибка «IIa» вместо «IIb» не видна глазу, поэтому шаг сверки обязателен.
Составные ячейки (bullets, вложенные критерии, как GRACE >140 на втором скрине): хранить структурой, не слитым текстом.
Авторское право. Таблицы ESC защищены. Для личного справочника это нормально, но если GitHub Pages публичный, то при публикации стоит держать репозиторий приватным или хотя бы указывать источник (citation) и не выкладывать всё подряд.
Версионирование: гайдлайны обновляются. В id закладывайте год (esc-acs-2023), а новую редакцию заводите как новый гайдлайн, а не перезаписью.
