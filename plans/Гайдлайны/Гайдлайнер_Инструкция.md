# Руководство и регламент агента «Гайдлайнер» (Starley Medical Library)

Настоящий документ содержит полное методическое и техническое руководство по созданию, валидации и интеграции интерактивных клинических руководств (ESC, AHA/ACC) на основе таблиц, схем и алгоритмов.

---

## 1. Архитектура и принципы подсистемы гайдлайнов

В последних коммитах приложения Starley Medical Library реализована и масштабирована подсистема интерактивных клинических гайдлайнов:
- Создано и внедрено **15 полных руководств** (10 ESC и 5 AHA/ACC), содержащих свыше **3 570 строк рекомендаций**.
- **Принцип «смысл важнее оформления»**: в данных JSON хранятся только семантические значения (`class`, `level`, `tone`), а визуальные цвета ячеек, бейджей и шрифтов определяются дизайн-токенами CSS в `assets/css/guideline-tables.css` с поддержкой темной/светлой тем и контрастностью не менее 4.5:1.
- **Двуязычность `{en, ru}`**: английский текст является эталоном и источником истины; русский перевод обеспечивает профессиональную академическую терминологию кардиологов и кардиохирургов.
- **Единый компонент и сквозной доступ**:
  - Каталог и просмотрщик `assets/js/guideline-tables.js` с режимом книги (листание таблиц стрелками `←` / `→`).
  - Быстрый доступ из режима чтения (`reader.html`).
  - Быстрый доступ из квиза (`quiz.html`) с автоматической паузой таймера тестирования.
  - Полнотекстовый поиск с фильтрами по классу и уровню доказательности (`search/search-ui.js`).
  - Интерактивный редактор таблиц (`guideline-editor.html`).

## 2. Различия между ассоциациями: ESC (Европа) и AHA/ACC (США)

| Параметр | Европейское общество кардиологов (ESC) | Американская коллегия / ассоциация (AHA/ACC) |
| :--- | :--- | :--- |
| **Файл легенды** | `data/guidelines/legends/esc-2023.json` | `data/guidelines/legends/aha-acc-2022.json` |
| **Классы (Class)** | `"I"`, `"IIa"`, `"IIb"`, `"III"` | `"I"`, `"IIa"`, `"IIb"`, `"III-no-benefit"`, `"III-harm"`, `"Value-High"`, `"Value-Intermediate"`, `"Value-Low"`, `"Value-Uncertain"` |
| **Уровни (Level)** | `"A"`, `"B"`, `"C"` | `"A"`, `"B-R"`, `"B-NR"`, `"C-LD"`, `"C-EO"` |
| **Интерпретация Class III** | Всегда единый класс III | Четкое разделение: «Нет пользы» (`III-no-benefit`) vs «Опасность/Вред» (`III-harm`) |
| **Оценка экономической ценности** | Не входит в классы | Включает утверждения ценности (`Value Statements`) |

## 3. Каталог файлов руководства (`data/guidelines/<id>/`)

Для каждого руководства создается отдельная папка:
- `guideline.json` — паспорт руководства, ссылки, DOI, легенда и словарь аббревиатур.
- `rtXX-<slug>.json` — таблицы рекомендаций (`type: "recommendations"`).
- `tXX-<slug>.json` — обычные таблицы, шкалы, дозировки (`type: "grid"`).
- `tXX-what-to-do.json` — итоговая сводная таблица ключевых положений «Что делать» (Class I) и «Чего не делать» (Class III).

## 4. Как обрабатывать схемы, алгоритмы и блок-схемы

1. **Диагностические и лечебные алгоритмы (Flowcharts / Decision Trees)**:
   - В клинической практике врач ищет алгоритмический ответ: «Что делать при условии X?».
   - Алгоритм переводится в таблицу `type: "recommendations"`:
     - Основные этапы или клинические группы становятся заголовками секций (`sections[]`).
     - Ветвления («Если признак A присутствует...», «При рефрактерности к терапии...») оформляются отдельными строками (`rows[]`) с соответствующими `class` и `level`.
     - Маркированные условия оформляются через `bullets[]`.
2. **Сравнительные матрицы выбора тактики** (например, «SAVR vs TAVI», «PCI vs CABG»):
   - Переводятся в `type: "grid"` с колонками критериев и подсветкой `tone` (`green`, `yellow`, `red`, `neutral`).

## 5. Полный регламент автономного агента «Гайдлайнер»

Когда агент «Гайдлайнер» получает задание (изображения, текст, PDF):
1. **Не задавать лишних вопросов**: сразу определить организацию, год и название руководства.
2. **Создать каталог** `data/guidelines/<guidelineId>/` и паспорт `guideline.json` (если руководство новое).
3. **Зарегистрировать** в `data/guidelines/guidelines.json`.
4. **Сформировать JSON файлов таблиц** строго по схеме (`schema/guideline-table.schema.json`).
5. **Выполнить валидацию**:
   ```powershell
   node tools/validate-tables.mjs
   ```
   Устранить любые ошибки схемы, расхождения сносок или некорректные классы.
6. **Сгенерировать таблицы и поисковые индексы**:
   ```powershell
   node tools/build-tables-index.mjs
   node search/generate-search-index.js
   ```
7. **Предоставить отчет пользователю** со сводкой добавленных таблиц, числом строк и ссылками для просмотра.
