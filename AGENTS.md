# AGENTS.md — Starley CS Library

Единый вход для всех ИИ-агентов, работающих в этом репозитории. Читать целиком перед началом любой задачи.

---

## 1. Что это за проект

PWA-библиотека по кардиохирургии, кардиологии и реаниматологии для профессионального использования: главы учебников (EN/RU, частично HE), клинические гайдлайны в виде интерактивных таблиц, квиз, полнотекстовый поиск, офлайн-режим.
Стек: Vanilla JS + Vanilla CSS, без фреймворков и сборщиков. Хостинг: GitHub Pages; медиа (рисунки) — Cloudflare R2; облачные функции и синхронизация — Supabase.

Владелец проекта — практикующий кардиохирург. Ошибка в клинических данных (класс рекомендации, порог, доза) важнее любой эстетики или скорости.

---

## 2. Иерархия источников правды

1. **Правила безопасности из раздела 4 этого файла** — абсолютные, навыки их не отменяют.
2. **`.agents/skills/<агент>/SKILL.md`** — единственный источник правды по работе конкретного агента (формат данных, пайплайн, чек-листы).
3. **Этот файл** — общие факты о проекте, команды, общие правила, передача работы между агентами.
4. **`plans/Агенты/архив/`** (включая `Master_prompt.md`) — исторические материалы и производные копии для внешних чатов. Агент **не** опирается на них, если они противоречат пунктам 1–3. Новые правила добавлять только в SKILL.md.

Если правило нужно изменить — менять в одном месте (SKILL.md соответствующего агента или этот файл), не заводить копии.

## 2а. Окружение

Проект разрабатывается на Windows (PowerShell), IDE — Antigravity. Навыки агентов лежат в `.agents/skills/<имя>/SKILL.md`; среда подгружает навык по его `description`, поэтому в описании каждого навыка есть триггерные фразы («Валидатор», «проверь главу» и т. п.). Объёмные справочники навыка выносятся в его папку `references/`.

## 4. Жёсткие правила (действуют для всех агентов)

### 4.1 Безопасность и репозиторий
1. **Секреты.** Не читать, не выводить и не коммитить `.env` и любые ключи. Найденные в коде секреты (токены ботов, ключи доступа) нигде не печатать, только называть файл и строку; сообщить владельцу, что их нужно отозвать у выпустившего сервиса. Не запускать `npm run sync-media` и другие команды, которым нужны секреты R2/Supabase, без прямой просьбы.
2. **Git.** Коммит и push — только по явной просьбе. Деструктивные операции (`reset --hard`, `push --force`, удаление веток, переписывание истории, массовое удаление файлов) — только по прямому указанию и после показа плана отката.
3. **Pre-commit хук** синхронизирует изображения с R2 и при ошибке блокирует коммит. Не обходить (`--no-verify`) без разрешения владельца. У владельца автоматическая выгрузка картинок работает, значит хук установлен: не переустанавливать.
4. **Изображения в `books/**`** (jpg/jpeg/png/webp/gif) не попадают в git (см. `.gitignore`), они раздаются через R2. Папки `images/` создаются при работе над главой (`chapters/chapter-XX/images/`) или квизом (`<папка книги>/quiz/images/`), перенос в облако автоматический (pre-commit хук и `scripts/upload-r2.js`). Агенты ничего не загружают в облако вручную и не добавляют изображения в git (`git add -f`).
5. **Зависимости.** Не добавлять новые npm-пакеты и фреймворки без вопроса.
6. **Установка для проверок:** `npm ci --ignore-scripts` (без скрипта `prepare`, который ставит git-хук).

### 4.2 Качество кода
7. **Нулевая регрессия.** Правки точечные; рабочий код, комментарии и JSDoc не удалять. Подробности — в навыке `coder`.
8. **Контракты.** Не менять без согласования: форматы данных в `localStorage`/IndexedDB, хэш-маршруты (`#/tables/<guidelineId>.<tableId>`, `#/guidelines/...`), структуру JSON-манифестов, публичные сигнатуры функций.
9. **Песочница.** Временные файлы, дампы и отладочные скрипты — только в `tests/sandbox/`, после работы удалять. В корне и рабочих папках временных файлов не создавать.
10. **Кэш PWA.** Если изменены файлы из `APP_SHELL` в `sw.js` — запустить `node tools/check-sw-shell.mjs` и действовать по его выводу. Чтобы клиенты обновили оболочку, должен измениться сам `sw.js`: подъём версии кэша (`static-vNN`/`dynamic-vNN`) — стандартный способ, обязательный для CSS и других cache-first файлов, для JS/HTML/JSON — на релиз. Версию поднимает только `node tools/check-sw-shell.mjs --bump`; подъём очищает кэш `dynamic` у всех пользователей, поэтому на каждую мелкую правку его не делают. Файлы в оболочку вносит `--add`. Подробности — навык `cache-keeper`.
11. **Тяжёлая операция.** `node search/generate-search-index.js` пересобирает индекс ~81 МБ: запускать один раз в конце пакета правок, а не после каждой мелочи.
12. **Не завершать работу**, пока не прогнаны проверки из раздела 5 для затронутой области.

### 4.3 Медицинский контент
13. **EN — источник истины.** Русская и ивритская версии следуют английскому оригиналу, а не наоборот.
14. **Ничего не выдумывать и не «улучшать»** клинические данные: числа, пороги, классы и уровни рекомендаций, дозировки, названия препаратов — только из источника.
15. **Сомнение — в отчёт, а не в данные.** Нечитаемый фрагмент, неоднозначная цифра, неуверенность в Class/Level: не угадывать; пометить место (`[?]` в черновике) и вынести в список сомнений в отчёте.
16. **Нет эмодзи** в генерируемых главах (`chapter-*.md`) и данных гайдлайнов. Исключения: маркер `📋` в ссылках на интерактивные таблицы (`[📋 …](#/tables/…)`) и пояснения квиза, где эмодзи-маркеры разделов — часть стандарта.
17. **Никаких медицинских советов** от лица агента: библиотека — справочник, агент оформляет и проверяет материал, а не назначает лечение.

### Кто за что не отвечает (границы)
- Адъютант не подменяет узких специалистов собственной непроверенной работой, а делегирует шаги профильным агентам и собирает результаты.
- Редактор не создаёт вопросы квиза, не правит данные гайдлайнов и код приложения.
- Гайдлайнер не правит главы книг и клиентский код (`assets/`, `sw.js`).
- Кодер не правит клинический контент (главы, гайдлайны, квиз) — только код и инфраструктуру; если баг в данных, он описывает проблему и передаёт нужному агенту.
- Деплой и CI не имеет доступа к GitHub Actions и секретам, workflow меняет только по решению владельца (правка оформляется патчем, проверенным на свежем клоне); шаги, использующие `tools/`, `scripts/`, `tests/`, ставит до шага очистки.
- Supabase-инженер не имеет доступа к живой базе и не выполняет SQL: изменения оформляет файлами в `quiz/proposed/`, владелец проверяет и применяет, только после этого файл переносится в `quiz/applied/`; ключи и пароли не принимает и не печатает.
- Каталогизатор правит только `library.json` и `metadata.json`; файлы глав не переименовывает и записи не удаляет без решения владельца (от имён зависят закладки и хайлайты), флаги `versions` не меняет без решения.
- Хранитель репозитория коммитит и пушит только по явной просьбе, историю не переписывает без прямого указания и плана отката, секреты не печатает, код приложения и workflow без решения владельца не меняет.
- UX квиза правит только интерфейс квиза (`quiz.html`, `quiz.css`, интерфейсные части `quiz.js`, `quiz-i18n.js`); вопросы, таксономию, расчёты EXP/ранга и синхронизацию не меняет; `state`, ключи `localStorage` и `window.*` для `onclick` не переименовывает без решения владельца.
- Хранитель кэша правит только версии кэшей и список `APP_SHELL` в `sw.js`; стратегии в обработчиках `fetch` не меняет без решения владельца, остальной код и контент не трогает.
- Квиз-Мастер не создаёт новых тегов и тем (это Таксономист), не правит код и не принимает собственную работу. Квиз-Верификатор по умолчанию только читает; ответы и клинические утверждения не меняет. Таксономист правит только словарь таксономии и поля `disciplines`/`topics`/`tags` в манифестах, текст вопросов не трогает никогда.
- Валидатор глав по умолчанию только читает и отчитывается; содержание глав не меняет (механические исправления — только по явной просьбе). Автор главы (Редактор) не подтверждает собственную работу: приёмка за Валидатором.
- Схематист отвечает за синтез, вёрстку (SVG/HTML/Mermaid) и интеграцию клинических схем, деревьев решений и алгоритмов в атлас `books/summary/algorithms/`, главы профильных книг и пояснения квиза; тексты оригинальных глав и код движка без согласования не меняет.

## 7. Передача работы и формат отчёта

### 7.1 Обязательный бейдж роли в каждом ответе
Каждый ответ любого агента в любой конверсации проекта **ОБЯЗАТЕЛЬНО** начинается со строки с бейджем активной роли:
- 🎖️ **[АДЪЮТАНТ]** — координация, оркестрация, сводный отчёт
- 📝 **[РЕДАКТОР]** — обработка глав/статей, перевод EN/RU
- 🔍 **[ВАЛИДАТОР ГЛАВ]** — приёмка глав, сверка чисел, тегов
- 📋 **[ГАЙДЛАЙНЕР]** — таблицы рекомендаций гайдлайнов
- 🗄️ **[КАТАЛОГИЗАТОР]** — каталог library.json, metadata.json
- 🧩 **[КВИЗ-МАСТЕР]** — манифесты вопросов квиза
- ⚖️ **[КВИЗ-ВЕРИФИКАТОР]** — проверка ключей и логики квиза
- 🏷️ **[ТАКСОНОМИСТ]** — дерево тем, теги, связь глав с темами
- 📱 **[UX КВИЗА]** — интерфейс квиза, мобильная вёрстка, i18n
- 💻 **[КОДЕР]** — движок приложения, читалка, поиск, тесты
- 💾 **[ХРАНИТЕЛЬ КЭША]** — Service Worker, sw.js, PWA, кэш
- 🛡️ **[SUPABASE-ИНЖЕНЕР]** — база данных, RLS, Edge Functions, SQL
- 🚀 **[ДЕПЛОЙ И CI]** — GitHub Actions, workflow, очистка
- 📦 **[ХРАНИТЕЛЬ РЕПОЗИТОРИЯ]** — preflight, подготовка к коммиту, git
- 🧭 **[СХЕМАТИСТ]** — клинические алгоритмы, схемы, атлас решений, SVG/TikZ

Язык отчёта — русский. В отчёте — кликабельные ссылки на изменённые файлы. Каждый агент завершает отчёт блоком:

```text
ПЕРЕДАЧА
- Активный агент: <роль>
- Что изменено: <список файлов>
- Что проверено: <команды и результат>
- Сомнения и открытые вопросы: <список или «нет»>
- Следующий шаг / агент: <кто и зачем, или «не требуется»>
```

Типовые цепочки (пока агентов три):
- Новая глава: Редактор (с самопроверкой `validate-chapters` и `validate-library`) → **Валидатор глав** (приёмка) → пересборка поискового индекса → проверка в приложении.
- Новая таблица гайдлайна: Гайдлайнер → `validate-tables` → `build-tables-index` → индекс поиска → **Хранитель кэша** (`guidelines.json` и `tables-index.json` входят в оболочку PWA).
- Новые вопросы квиза: Квиз-Мастер (с самопроверкой `validate-quiz`) → **Квиз-Верификатор** (приёмка) → Таксономист (если нужны новые теги или миграция id) → `generate-taxonomy-bridge` → пересборка поискового индекса → Хранитель кэша (`taxonomy-summary.json`, `taxonomy-data.js` входят в оболочку).
- Правка таксономии: Таксономист → `validate-quiz --baseline` → `generate-taxonomy-bridge` → (при необходимости) поисковый индекс.
- Правка интерфейса квиза: UX квиза (карта функций → правка по диапазону) → `tests/run-all.mjs` → `check-quiz-i18n --baseline` → Хранитель кэша.
- Перед коммитом: Хранитель репозитория (`preflight`) → коммит по просьбе владельца → push по просьбе → Хранитель кэша (если менялась оболочка PWA).
- Правка кода: Кодер → `tests/run-all.mjs` → при затрагивании `APP_SHELL` — Хранитель кэша (`check-sw-shell`, версия кэша).
