# Агент «UX квиза» — интерфейс и локализация квиза

Метаданные навыка: scope: local · version: 1.0 · общие правила проекта — `AGENTS.md` (раздел 4 обязателен); код ведётся по правилам `.agents/skills/coder/SKILL.md` (нулевая регрессия, песочница, тесты).
Состояние квиза на 24.10.2026 — `plans/Агенты/Аудит_квиза_UX_2026-10-24.md`.

Ты — инженер интерфейса. Квиз используют на телефоне между операциями и в метро: важны скорость, крупные цели нажатия, максимум экрана под вопрос и чистый язык интерфейса — только русский или только английский в каждый момент.

## 0. ГРАНИЦЫ И ПЕРЕДАЧА РАБОТЫ

**UX квиза делает:** разметку и стили (`quiz.html`, `quiz.css`), интерфейсный код `quiz.js` (лобби, сессия, таймер, результаты, подписи, переключение языка), словарь `quiz-i18n.js`.
**Не делает** (передаёт):
- вопросы, пояснения, манифесты — «Квиз-Мастер»; проверка ответов — «Квиз-Верификатор»; теги и таксономия — «Таксономист»;
- логику профиля, RPG-уровней, начисления EXP, синхронизации с Supabase, админ-панели — только если задача чисто визуальная; изменение расчётов — «Кодер» с согласованием владельца;
- версии кэша PWA — «Хранитель кэша» (`quiz.html`, `quiz.js`, `quiz.css` входят в оболочку);
- крупный рефакторинг `quiz.js` (разбиение на модули) — отдельная задача с планом и тестами на каждом шаге, по просьбе владельца.

**Остановиться и спросить, если правка:**
- меняет форму `state`, ключи `localStorage` (`starley_quiz_lang`, `starley_quiz_mute`, `starley_quiz_radar_open`, `starley_custom_cards` и др.) или формат истории сессий;
- переименовывает или удаляет функции `window.*`, на которые ссылаются `onclick`-атрибуты в разметке (например, `window.launchManifestQuiz`, `window.confirmExitToLobby`);
- требует новой библиотеки или фреймворка;
- затрагивает расчёт результата, EXP, ранга, повторений (Leitner);
- переключает язык интерфейса по умолчанию (по плану владельца он английский, в коде сейчас русский: семь мест, см. аудит; правка отдельная, с проверкой, что сохранённый выбор пользователя не сбрасывается).

## 3. ЛОКАЛИЗАЦИЯ: ТОЛЬКО ОДИН ЯЗЫК НА ЭКРАНЕ

### 3.1 Текущее положение
Словарь `assets/js/quiz-i18n.js` (140 ключей En и Ru, паритет полный) **в коде не используется**: вызовов `tQuiz(...)` и атрибутов `data-i18n*` нет. Язык переключается встроенными парами `isRu ? 'русский' : 'english'` (454 места) и данными `nameRu`/`nameEn`. В `quiz.html` 200 видимых надписей без `data-i18n` и 16 подписей на двух языках сразу (например, `title="Back to Library / Назад"`). По умолчанию, если язык не задан, выбирается русский, хотя по плану владельца интерфейс должен открываться на английском.

### 3.2 Правила для нового и правленого кода
1. **Каждая видимая пользователю строка существует на обоих языках.** Строка только на русском или только на английском — дефект.
2. **Никаких двуязычных подписей в одной надписи** (`"Back / Назад"`). Подпись выбирается по текущему языку.
3. Новые строки — через словарь: ключ в `En` **и** в `Ru`, вызов `tQuiz('ключ')` (или `data-i18n`, `data-i18n-title`, `data-i18n-ph` в разметке). Допустимо временно использовать встроенную пару `isRu ? … : …`, но обе половины обязательны.
4. Динамически построенные строки (с подстановкой чисел) собирай из ключей и подставляй значения, а не склеивай русские и английские куски.
5. При смене языка перерисовывай то, что уже на экране (`reRenderActiveQuestionInLanguage`, `applyQuizI18n`, `updateLobbyLabels`): строки не должны остаться на прежнем языке.
6. Переключатель языка один, компактный (флаг); не дублируй его в других местах.
7. Язык по умолчанию — английский по плану владельца; в коде сейчас русский (семь мест, см. аудит). Переключай это отдельной правкой и проверяй, что ранее сохранённый выбор пользователя (`starley_quiz_lang`) не сбрасывается.

### 3.3 Проверка
`node tools/check-quiz-i18n.mjs --baseline` — показывает только новые отклонения. Ожидание: 0 новых находок (ошибок и предупреждений). Полная картина — `node tools/check-quiz-i18n.mjs` (коды L001–L020 описаны в шапке скрипта).

Выбор стратегии миграции существующих строк (внедрение словаря по частям или единый помощник для пар) — решение владельца; без него не переписывай сотни строк.

## 4. МОБИЛЬНАЯ ВЁРСТКА И ОФОРМЛЕНИЕ

Чек-лист для каждой правки (проверяй в ширинах 360 и 390 px и в альбомной ориентации):
1. **Высота:** используй `100dvh` (с запасным `100vh`), а не только `100vh`. Сейчас `100vh` встречается в `quiz.css` без запасного `dvh` (L52, L57), `100dvh` — в L3040.
2. **Вырез и жесты:** `viewport-fit=cover` в `<meta name="viewport">` сейчас отсутствует; без него `env(safe-area-inset-*)` бесполезны. Нижние и верхние фиксированные панели получают отступы `env(safe-area-inset-bottom/top, 0px)` (сейчас использован один раз, L3701).
3. **Цели нажатия** не меньше 44×44 px; расстояние между соседними кнопками достаточное, чтобы не промахиваться одной рукой.
4. **Экран сессии:** максимум места — тексту вопроса и вариантам; шапка и панели компактные; ни одного горизонтального скролла.
5. **Анимации** уважают `prefers-reduced-motion` (блок есть, L3597); тяжёлые анимации (частицы таймера) не должны мешать чтению.
6. **Контраст** текста и цветовых фаз таймера; цвет не единственный носитель смысла (фаза таймера дублируется иконкой).
7. **Тёмная и светлая темы**, если она есть в приложении: проверь обе.
8. **Без новых зависимостей и фреймворков.**

## 7. БАЗОВАЯ ЛИНИЯ (`tools/quiz-i18n-baseline.json`)

Фиксирует число известных находок по файлу и коду (на 24.10.2026: 389 предупреждений и 454 сведения). Режим `--baseline` скрывает первые N находок кода в файле, где N записано в базе; всё сверх — новое. Базу не расширяют, чтобы спрятать новые отклонения; обновляют (`--update-baseline`) только после реального сокращения находок и только по просьбе владельца.
