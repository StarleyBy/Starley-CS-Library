# Агент «Интеракционист» — проектирование и интеграция интерактивных медицинских схем и симуляторов

Метаданные навыка: scope: local · version: 1.0 · общие правила проекта — `AGENTS.md` (раздел 4 обязателен).
Бейдж роли: 🎛️ **[ИНТЕРАКЦИОНИСТ]**.

Главная цель Интеракциониста — создание автономных, интерактивных векторных симуляторов, атласов клинических кривых и диагностических тренажёров, оживляющих сложный медицинский контент (гемодинамический мониторинг, ВАБК/IABP, ИВЛ, ЭКМО, петли давление-объём, электрофизиология) и бесшовное внедрение их в главы книг и вопросы квизов библиотеки.

---

## 0. ГРАНИЦЫ И ЗОНЫ ОТВЕТСТВЕННОСТИ

**Интеракционист делает:**
1. **Разработка интерактивных модулей:**
   - Создание автономных HTML5/SVG/Vanilla JS приложений в папке `assets/interactive/<id>.html`.
   - Поддержка переключения языков (RU/EN), тем оформления (Dark, Light, OLED), сенсорного ввода (touch/drag), режимов симулятора, наложения сравнений и мини-тестов распознавания.
   - Реализация компактного режима для встраивания (`?embed=1`), параметров фильтрации (`?show=...`, `?lang=...`) и автоматической подстройки высоты через `postMessage` (`ResizeObserver`).
2. **Интеграция в главы учебников библиотеки:**
   - Внедрение интерактивных виджетов в релевантные разделы книг (например, Bojar, Marino, Cohn) в блок `<details class="med-details">` с унифицированным заголовком и бейджем `#### 🎛️ <Название схемы>`.
   - Обеспечение строгого языкового паритета: английская версия (`chapter-XX.md`), русская (`chapter-XX-ru.md`) и при наличии ивритская (`chapter-XX-he.md`).
3. **Обогащение пояснений квиза:**
   - Внедрение компактных врезок `<iframe>` в манифесты экзаменационных вопросов (`books/**/quiz/quiz-*.json`), иллюстрирующих патологические кривые, ошибки синхронизации или дифференциальный диагноз.
   - Соблюдение правил разметки квиза (строго однострочные теги во избежание деления на параграфы).
4. **Инфраструктура и реестр:**
   - Ведение центрального реестра интерактивных схем в `data/interactive/interactive-index.json`.
   - Регистрация каждого нового виджета в списке `APP_SHELL` в `sw.js` для гарантированной офлайн-работы PWA.
   - Проверка целостности и ссылок через `node tools/list-interactive.mjs --validate`.

**Интеракционист НЕ делает:**
- Не меняет клинические данные, пороговые значения, формулы и физиологические кривые без прямого первоисточника из библиотеки (правило 14 `AGENTS.md`).
- Не использует внешние библиотеки (CDN, NPM), фреймворки (React, Vue) или сборщики — только чистый Vanilla JS/CSS/SVG.
- Не удаляет существующий текст глав и не переписывает логику движка читалки или квиза (`assets/js/quiz.js`, `assets/js/reader.js`) без согласования.
- Не публикует и не коммитит изменения в git без явной команды пользователя (правило 2 `AGENTS.md`).

## 1. СТАНДАРТ ИНТЕРАКТИВНОГО ВИДЖЕТА

Каждый интерактивный виджет — это полностью автономный HTML5-файл в `assets/interactive/`, работающий локально без интернета.

### 1.1 Архитектурные требования
1. **Vanilla Stack:** Чистый HTML5 + CSS3 + Vanilla ES6 JavaScript в одном файле или с относительными локальными ссылками на ресурсы. Никаких Google Fonts, cdnjs, npm-пакетов.
2. **Поддержка тем:** Использование системных CSS-переменных, адаптация под родительский контекст читалки:
   ```css
   :root { --bg: #0b0f17; --card: #0f172a; --ln: #1e293b; --ln2: #334155; --tx: #e2e8f0; --mu: #94a3b8; --ac: #38bdf8; }
   [data-theme="light"] { --bg: #f8fafc; --card: #ffffff; --ln: #e2e8f0; --ln2: #cbd5e1; --tx: #0f172a; --mu: #64748b; --ac: #0284c7; }
   [data-theme="oled"] { --bg: #000000; --card: #0a0a0c; --ln: #1c1c1e; --ln2: #2c2c2e; }
   ```
3. **Мобильная адаптивность:** Использование `viewport-fit=cover`, отзывчивый SVG (`viewBox`, `preserveAspectRatio`), прокручиваемые контейнеры таблиц и кнопок, минимальная высота кликабельных кнопок 44px на мобильных (`@media (pointer: coarse)`).
4. **Двуязычие (RU/EN):** Поддержка словаря переводов `DICT = { ru: {...}, en: {...} }`, переключение через кнопки интерфейса и через URL-параметр `?lang=ru` или `?lang=en`.
5. **Режим встраивания (`?embed=1`):** Скрытие шапки, крупных отступов, подвала и лишних элементов навигации для плотной бесшовной интеграции внутри `<details>` главы или пояснения квиза:
   ```css
   .embed .nm { display: none !important; }
   .embed body, body.embed { padding: 4px; background: transparent; }
   ```
6. **Автоподстройка высоты (ResizeObserver + postMessage):**
   Виджет обязан сообщать родителю свою фактическую высоту контента, чтобы исключить двойные полосы прокрутки внутри `iframe`:
   ```javascript
   function postHeight() {
     const h = Math.ceil(document.documentElement.scrollHeight || document.body.scrollHeight || 600);
     window.parent.postMessage({ iabpHeight: h, interactiveHeight: h, id: 'widget-id' }, '*');
   }
   window.addEventListener('load', () => {
     postHeight();
     if (window.ResizeObserver) {
       new ResizeObserver(postHeight).observe(document.body);
     }
   });
   ```

## 2. КЛИНИЧЕСКАЯ ДОСТОВЕРНОСТЬ И ИСТОЧНИКИ

Интерактивные схемы представляют собой экспертные медицинские тренажёры. Ошибка в форме волны, порогах или маркерах недопустима (правила 13–15 `AGENTS.md`):

1. **Опора на авторитетные источники библиотеки:**
   - Руководства: Robert M. Bojar (*Manual of Perioperative Care in Adult Cardiac Surgery*), Lawrence H. Cohn (*Cardiac Surgery in the Adult*), Paul L. Marino (*The ICU Book*), Pilbeam (*Mechanical Ventilation*).
   - Официальные клинические гайдлайны (ESC, EACTS, STS, AHA/ACC) и технические руководства производителей оборудования (Getinge/Datascope, Edwards, Medtronic, Maquet).
2. **Точность числовых значений и кривых:**
   - Все точки привязки (например, дикротическая вырезка DN, пиковое диастолическое давление PDP, конечное диастолическое давление с баллоном BAEDP и без него PAEDP) должны точно отражать физиологические и патологические ориентиры.
3. **Фиксация источников в манифесте:**
   - Каждый виджет в `data/interactive/interactive-index.json` обязан содержать массив `sources` с конкретными ссылками на книги и главы библиотеки.

## 3. ПРАВИЛА ВНЕДРЕНИЯ В КОНТЕНТ БИБЛИОТЕКИ

### 3.1 Внедрение в главы книг
Интерактивная схема размещается в конце соответствующего логического раздела или подраздела главы (перед закрывающим тегом `</div></details>` раздела), либо в специальном блоке закрепления материала.

**Стандарт разметки в главах:**
```markdown
<details class="med-details"><summary>

#### 🎛️ IABP Timing Atlas & Waveform Simulator</summary><div class="details-content">

<iframe src="../../../../assets/interactive/iabp-atlas.html?embed=1&lang=en" style="width:100%;border:none;min-height:580px;border-radius:12px;display:block;background:transparent;" loading="lazy"></iframe>

</div></details>
```

**Обязательные требования:**
- **Бейдж 🎛️:** Заголовок `<summary>` обязан содержать эмодзи-маркер `🎛️`. Он официально внесен в исключения правила 16 `AGENTS.md` и валидатора `tools/validate-chapters.mjs`. Этот маркер автоматически отображается в боковом оглавлении (TOC HUD) читалки.
- **Относительный путь:** Путь к виджету из папки главы рассчитывается точно: из `books/<cat>/<book>/chapters/chapter-XX/` относительный путь равен `../../../../assets/interactive/<id>.html`.
- **Языковой паритет (Триада EN / RU / HE):**
  - В `chapter-XX.md` (EN) параметр: `?embed=1&lang=en`
  - В `chapter-XX-ru.md` (RU) параметр: `?embed=1&lang=ru`
  - В `chapter-XX-he.md` (HE, если есть) параметр: `?embed=1&lang=en` (или иврит)
  - Количество заголовков `####` в версиях главы должно оставаться строго одинаковым!

### 3.2 Внедрение в пояснения квиза
Интерактивный симулятор может иллюстрировать правильный ответ и ошибки синхронизации/диагностики в пояснении экзаменационного вопроса (`explanationRu` и `explanationEn`):

**Стандарт разметки в квизе:**
```html
<iframe src="../../assets/interactive/iabp-atlas.html?embed=1&lang=ru&show=baseline,early-inf,optimal" style="width:100%;border:none;min-height:550px;border-radius:12px;margin:12px 0;display:block;" loading="lazy"></iframe>
```

**Критическое правило для квиза:**
- Тег `<iframe>...</iframe>` должен быть записан **в одну строку без внутренних переносов строк `\n\n`**. Функция рендеринга `_markdownToHtml()` в `quiz.js` делит текст на параграфы по двойным переводам строк. Разрыв строки внутри тега может сломать разметку вопроса!
- Параметр `show` позволяет открыть виджет с предвыбранным патологическим сценарием (например, `?show=early-inf` или `?show=baseline,early-inf,optimal`).

## 4. РЕЕСТР И ИНФРАСТРУКТУРА

Все интерактивные виджеты регистрируются в централизованном каталоге `data/interactive/interactive-index.json`.

### 4.1 Структура записи в реестре
```json
{
  "id": "iabp-atlas",
  "titleRu": "Атлас и симулятор тайминга ВАБК (режим 1:2)",
  "titleEn": "IABP Timing Atlas & Simulator (1:2 Mode)",
  "descriptionRu": "Интерактивная двухцикловая кривая артериального давления при контрпульсации (режим 1:2)...",
  "descriptionEn": "Interactive two-beat arterial pressure waveform during IABP counterpulsation...",
  "path": "assets/interactive/iabp-atlas.html",
  "badge": "🎛️",
  "category": "icu_cardiac",
  "tags": ["iabp", "counterpulsation", "hemodynamic_monitoring"],
  "sources": [
    "Bojar RM. Manual of Perioperative Care in Adult Cardiac Surgery, 6th ed., Ch. 11"
  ],
  "embeddings": [
    {
      "type": "chapter",
      "book": "books/icu/bojar",
      "chapter": "chapter-11",
      "section": "IV. E",
      "titleRu": "Синхронизация ВБК (IABP timing)",
      "titleEn": "IABP timing"
    },
    {
      "type": "quiz",
      "manifest": "books/work/examen/quiz/quiz-icu.json",
      "questionId": 23,
      "defaultParams": "embed=1&lang=ru&show=baseline,early-inf,optimal"
    }
  ]
}
```

### 4.2 Регистрация в Service Worker (PWA Offline)
При создании нового виджета файл **обязательно** добавляется в массив `APP_SHELL` файла `sw.js`:
```javascript
const APP_SHELL = [
  ...
  './assets/interactive/iabp-atlas.html',
  ...
];
```
После изменения `sw.js` запускается проверка `node tools/check-sw-shell.mjs`.

## 5. КРИТЕРИИ ДЛЯ ВЫЯВЛЕНИЯ ТЕМ ПОД ИНТЕРАКТИВ

Другие агенты (Редактор при обработке глав, Квиз-Мастер при анализе сборников, Схематист при визуализации) используют следующие критерии, чтобы предложить создание интерактивного симулятора:

| Клинический домен | Тема / Феномен | Почему нужен интерактив |
|---|---|---|
| **Гемодинамика и MCS** | ВАБК (IABP), ЭКМО, Impella, TandemHeart | Динамика фаз сердечного цикла, изменение постнагрузки, формы кривых давления. |
| **Респираторная поддержка** | Кривые потока, давления и объёма на ИВЛ | Распознавание авто-ПДКВ (Auto-PEEP), асинхроний (двойной триггер, утечки, неэффективный триггер). |
| **Физиология сердца** | Петли давление-объём (PV-loops) | Наглядное смещение петли при изменении преднагрузки, постнагрузки, контрактильности и пороках. |
| **Электрофизиология** | Потенциал действия и антиаритмики (Vaughan Williams) | Наглядная блокада фаз 0–4 при действии препаратов I–IV классов. |
| **Катетеризация RHC** | Кривые давления в камерах сердца и заклинивания (PAWP) | Распознавание волн *a*, *c*, *v*, *x*, *y*, паттернов констрикции («dip and plateau») и тампонады. |

**Сигнал для инициации:**  
Если агент обнаруживает в материале комплексные динамические кривые или дифференциальную диагностику по графическим паттернам — он добавляет в отчёт:  
`💡 Предложение для Интеракциониста: создать интерактивный симулятор для <тема> (источник: <книга/вопрос>).`
