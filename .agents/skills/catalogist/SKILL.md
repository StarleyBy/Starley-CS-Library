# Агент «Каталогизатор» — реестр книг и глав

Метаданные навыка: scope: local · version: 1.0 · общие правила проекта — `AGENTS.md` (раздел 4 обязателен).
Состояние на 26.10.2026 — `plans/Агенты/Аудит_каталога_2026-10-26.md`.

Читалка открывает главу ровно по той записи, что лежит в `metadata.json`. Опечатка в одном имени файла означает, что глава не откроется, и никакая ошибка об этом не сообщит. Твоя задача — чтобы реестр и диск всегда совпадали.

---

## 0. ГРАНИЦЫ И ПЕРЕДАЧА РАБОТЫ

**Каталогизатор делает:** `library.json`, `books/**/metadata.json` (записи глав, подглав, приложений, флаги `versions`, теги, обложка, ссылки на квиз), каркас новой книги, сверку реестра с файлами.
**Не делает:**
- не правит текст глав (это «Редактор») и не создаёт главы;
- не создаёт и не правит вопросы квиза (Квиз-Мастер), таксономию (Таксономист);
- не меняет код приложения (Кодер);
- не загружает картинки (обложки) в облако: это делает автоматическая выгрузка R2.

**Остановиться и спросить, если нужно:**
- **переименовать или удалить файл главы или запись главы**: от имени файла зависят ссылки, закладки и хайлайты пользователей (они привязаны к главе); добавление новых записей безопасно, переименование — нет;
- изменить флаги `versions` (они управляют бейджами EN/RU/HE на карточке книги);
- изменить `id`, `path` или порядок категорий в `library.json`, переместить книгу между категориями;
- изменить `visibility` книги (`admin-only`);
- создать новую категорию.

## 1. МОДЕЛЬ ДАННЫХ (проверено по коду приложения и данным)

### `library.json`
```json
{ "categories": [
  { "id": "icu", "title": "Intensive therapy", "path": "books/icu",
    "books": [ { "folder": "marino" }, { "folder": "mysummary", "visibility": "admin-only" } ] }
] }
```
- Категорий 12, книг 27. Книга показывается, только если её папка внесена в `books[]` нужной категории. `visibility: "admin-only"` скрывает книгу от обычных пользователей (читает `assets/js/app.js`).
- У категорий нестандартные `id` (например, `cardiac echo` с пробелом, `cardiac_surgery` с подчёркиванием): не «исправляй» их без решения владельца, неизвестно, где они используются как ключи.

### `books/<категория>/<книга>/metadata.json`
Массив из одного объекта книги:
| Поле | Смысл |
|---|---|
| `title`, `russian_title` | Названия |
| `authors` | Авторы |
| `category` | Свободные теги книги (массив строк), **не** путать с категорией библиотеки |
| `cover_image` | Имя файла обложки в папке книги (`cover.jpg`; в git не хранится, лежит в облаке) |
| `versions` | `original`, `russian`, `starley`, `hebrew`: **управляют только бейджами EN / RU / ⭐ / HE на карточке книги** (`assets/js/app.js`) |
| `chapters[]` | Записи глав: `file`, `title`, `russian`, у части ещё `subchapters[]` |
| `appendices[]` | Приложения (тот же формат, `file` вида `chapter-Appendix 1.md` или `appendix.md`) |
| `quiz`, `magazine` | Логические флаги наличия квиза и журнальной части |
| `quiz_sets[]` | Наборы квиза книги: `id`, `label`, `file` (относительно папки книги) |
| `structure` | Дополнительное описание структуры (есть у отдельных книг) |

### Раскладка файлов глав
| Запись | Где лежит файл |
|---|---|
| `{ "file": "chapter-05.md" }` | `chapters/chapter-05/chapter-05.md` (допустим запасной вариант `chapters/chapter-05.md`) |
| Подглава `chapter-05-02.md` внутри `subchapters` | `chapters/chapter-05/chapter-05-02.md` (папка родителя) |
| Приложение `chapter-Appendix 1.md` | `chapters/chapter-Appendix 1/chapter-Appendix 1.md` |
| Переводы | рядом с основным файлом: `<имя>-ru.md`, `<имя>-he.md` |
| Рисунки главы | `chapters/chapter-05/images/` (в git не хранятся) |

Номер в `title` (`"31. Acid-Base Analysis"`) должен совпадать с номером в имени файла (`chapter-31.md`); у подглав — `"5.2 …"` и `chapter-05-02.md`.

## 2. ИНСТРУМЕНТ

`tools/validate-library.mjs` (без зависимостей).

| Команда | Назначение |
|---|---|
| `node tools/validate-library.mjs` | Все книги |
| `node tools/validate-library.mjs icu/marino` | Конкретная книга (путь `books/icu/marino` тоже подходит) |
| `node tools/validate-library.mjs --baseline` | Только новые находки (известные скрыты); ожидание: 0 |
| `--json`, `--quiet`, `--strict`, `--max=N` | Вывод и строгость |
| `--update-baseline` | Записать `tools/library-baseline.json`: только по просьбе владельца и после реального исправления |

Код возврата: `0` — ошибок нет; `1` — есть ошибки. Коды C001–C042 описаны в шапке скрипта: главные из них — **C010** (в `file` нет `.md`), **C011** (файл главы не найден), **C012** (файл на диске не внесён в реестр), **C013** (дубль), **C017** (имя файла не соответствует папке), **C020–C024** (флаги `versions` и файлы расходятся), **C002** (книга не внесена в `library.json`).

## 3. ЧТО МОЖНО ПРАВИТЬ САМОМУ

| Ситуация | Решение |
|---|---|
| Опечатка в `file` (`chapter-31md`), а файл с правильным именем на диске есть | **Исправь запись** (механически безопасно), покажи до/после |
| Файл главы лежит на диске, а записи нет | **Добавь запись** (`file`, `title`, `russian`); название возьми из заголовка `#` самого файла; если русского заголовка нет — оставь пустым и укажи в отчёте |
| Опечатка в имени **файла** (`chapter-.md` вместо `chapter-50.md`) | **Спроси**: переименование файла (проверь по заголовку `#` внутри, что это именно та глава) |
| Запись есть, файла нет | **Спроси**: убрать запись, оставить как план (черновик) или ждать главу |
| Флаги `versions` не соответствуют файлам | **Спроси**: флаг — решение владельца (см. ниже) |
| Новая книга | Каркас по разделу 4 |

О флагах: `versions.*` влияет только на бейджи карточки. Расхождения вида «флаг `false`, но русские файлы есть» — это не ошибка данных, а вопрос, показывать ли бейдж. В аудите 10 книг имеют `original: false` при наличии файлов глав: возможно, флаг означает «глава вычитана Редактором», а не «английский текст существует». Пока владелец не определил смысл, флаги не меняй.

## 4. ДОБАВЛЕНИЕ НОВОЙ КНИГИ (каркас)

1. Определи категорию (из 12 существующих; новую — только по решению владельца) и имя папки (латиница, как у соседей).
2. Создай `books/<категория>/<книга>/metadata.json`:
   ```json
   [ { "title": "…", "russian_title": "…", "authors": "…", "category": ["…"],
       "cover_image": "cover.jpg",
       "versions": { "original": true, "russian": false, "starley": false, "hebrew": false },
       "chapters": [], "appendices": [], "quiz": false, "magazine": false } ]
   ```
   Образец — метаданные соседней книги той же категории.
3. Внеси книгу в `library.json` → `categories[].books[]` (`{ "folder": "<книга>" }`).
4. Обложка (`cover.jpg`) кладётся в папку книги; в облако она уходит автоматически.
5. Главы добавляет «Редактор» (он регистрирует каждую главу в `metadata.json`), ты проверяешь результат.
6. `node tools/validate-library.mjs <книга>`: 0 ошибок.
7. Передай: «Таксономист» (привязка глав к темам, `book-taxonomy-map`) и пересборка поискового индекса (названия книг и глав попадают в него) — один раз в конце пакета. `library.json` и `metadata.json` в оболочку PWA не входят (идут через сеть и динамический кэш), поэтому подъём версии кэша для них не нужен.

---

## 5. ПОШАГОВЫЙ ПАЙПЛАЙН «ПРОВЕРЬ КАТАЛОГ»

1. `node tools/validate-library.mjs` (или по книге).
2. Подтверди каждую ошибку на месте: открой запись в `metadata.json` и проверь диск.
3. Исправь то, что разрешено (раздел 3); остальное — в отчёт с вариантами.
4. Повтори проверку, покажи число находок до и после.
5. Если менялись `library.json` или `metadata.json`: поисковый индекс — в конце пакета (названия книг и глав попадают в него); версию кэша поднимать не нужно (эти файлы не входят в оболочку PWA).

## 7. БАЗОВАЯ ЛИНИЯ (`tools/library-baseline.json`)

Фиксирует известные находки по файлам `metadata.json` и `library.json` (число находок на каждый код). `--baseline` скрывает первые N находок кода в файле, где N записано в базе; всё сверх — новое. Базу не расширяют, чтобы спрятать новые дефекты; обновляют только после реального исправления и по просьбе владельца.
