### 1.2. Единый i18n-слой (корень проблемы №3)

Правило: **в HTML и JS не должно быть ни одной «голой» строки для пользователя.**

```js
const I18N = {
  en: { start:'Start Quiz', skip:'Skip', pause:'Paused', calc:'Calculator', draw:'Draw',
        bySets:'By sets', byDisc:'By disciplines', presets:'Questions', ... },
  ru: { start:'Начать квиз', skip:'Пропустить', pause:'Пауза', calc:'Калькулятор', draw:'Рисование',
        bySets:'По сборникам', byDisc:'По дисциплинам', presets:'Вопросы', ... }
};
let LANG = localStorage.getItem('lang') || 'en';
const t = k => (I18N[LANG][k] ?? (console.warn('i18n miss', k), I18N.en[k] ?? k));

function applyLang(){
  document.documentElement.lang = LANG;
  document.querySelectorAll('[data-i18n]').forEach(el => el.textContent = t(el.dataset.i18n));
  document.querySelectorAll('[data-i18n-ph]').forEach(el => el.placeholder = t(el.dataset.i18nPh));
  document.querySelectorAll('[data-i18n-title]').forEach(el => el.title = t(el.dataset.i18nTitle));
  document.querySelectorAll('[data-i18n-aria]').forEach(el => el.setAttribute('aria-label', t(el.dataset.i18nAria)));
  window.dispatchEvent(new Event('langchange')); // динамические списки перерисовываются
}
```

- Единственный переключатель языка: кнопка-флаг 🇬🇧/🇷🇺 в шапке. Блок «Select Language» удаляется из лобби, а в кабинете остаётся ссылка на тот же `setLang()`.
- **Автотест на утечку языка:** скрипт обходит все видимые текстовые узлы в режиме EN и ищет кириллицу, а в режиме RU ищет латиницу (кроме белого списка: EXP, Lv, ID, названия книг, «Kirklin»). Любое срабатывание блокирует релиз.

```js
// Консольный/Playwright-скрипт
const walker = document.createTreeWalker(document.body, NodeFilter.SHOW_TEXT);
const bad = []; 
while (walker.nextNode()) {
  const n = walker.currentNode, s = n.textContent.trim();
  if (!s || n.parentElement.closest('script,style,[data-i18n-skip]')) continue;
  const vis = n.parentElement.offsetParent !== null;
  if (!vis) continue;
  if (LANG==='en' && /[А-Яа-яЁё]/.test(s)) bad.push(s);
  if (LANG==='ru' && /[A-Za-z]{3,}/.test(s) && !WHITELIST.test(s)) bad.push(s);
}
```

Это касается и текстов, которые генерируются динамически: тосты, `confirm()`, `alert()`, сообщения об ошибках, заголовки модалок. Контент вопросов и объяснений берётся из манифестов по выбранному языку, там отдельный контроль.

### 1.3. Единая «машина состояния» сессии

Чтобы таймер, пропуски, навигация и вопросы не конфликтовали, нужен один объект состояния:

```js
const S = {
  deck: [],           // массив id вопросов в порядке показа (очередь)
  answers: {},        // id -> {choice, correct, ms, skippedCount}
  idx: 0,             // текущая позиция в deck
  skipped: new Set(), // id, отложенные в конец
  timer: { limitSec: 0, elapsedMs: 0, running: false, startedAt: 0, paused: false, phase: 0 }
};
```

Все виджеты читают состояние и вызывают `render()`. Прямых манипуляций DOM из разных мест быть не должно.

## 2. Реализация по пунктам

### 2.1. Таймер

**Логика**: время считаем по `performance.now()`, а не по `setInterval` с инкрементом, иначе на телефоне при сворачивании вкладки таймер «уплывёт».

```js
const TIMER = { tick:null };
function sessionLimit(n){ return n * 60; }           // секунд

function startTimer(n){
  S.timer = { limitSec: sessionLimit(n), elapsedMs: 0, running: true, startedAt: performance.now(), phase: 0 };
  loop();
}
function loop(){
  clearInterval(TIMER.tick);
  TIMER.tick = setInterval(() => {
    if (!S.timer.running) return;
    const now = performance.now();
    S.timer.elapsedMs += now - S.timer.startedAt;
    S.timer.startedAt = now;
    updateTimerUI();
  }, 250);
}
function toggleTimer(){                              // тап по таймеру
  const T = S.timer;
  if (T.running){ T.elapsedMs += performance.now()-T.startedAt; T.running=false; }
  else { T.startedAt = performance.now(); T.running = true; }
  renderTimer();
}
document.addEventListener('visibilitychange', () => { // не терять время при сворачивании
  if (document.hidden && S.timer.running) { S.timer.elapsedMs += performance.now()-S.timer.startedAt; S.timer.startedAt = performance.now(); }
});
```

**Фазы** (точно по вашему примеру 40 вопросов: 28:00 / 36:00 / 40:00):

```js
function phaseOf(elapsedSec, limitSec){
  const r = elapsedSec / limitSec;
  if (r <= 0.70) return 0;   // зелёный, цветы
  if (r <= 0.90) return 1;   // жёлтый, листья
  if (r <= 1.00) return 2;   // красный, капли
  return 3;                  // коричневый, мухи
}
const fmt = s => `${Math.floor(s/60)}:${String(Math.floor(s%60)).padStart(2,'0')}`;
```

Сверка с вашим примером: при `limit=2400` фаза 0 длится до 1680 сек (28:00), фаза 1 до 2160 (36:00), фаза 2 до 2400 (40:00), дальше фаза 3. Граница «28:01» корректно попадает в жёлтую зону, потому что сравнение нестрогое только сверху (`<=`). Это обязательный юнит-тест.

**Что показывать после 100%:** считать вверх (40:01, 40:02…), цвет коричневый.

**Звук щелчка** без внешних файлов (WebAudio, не требует загрузки, работает офлайн в PWA):

```js
let AC;
function click(){
  try{
    AC = AC || new (window.AudioContext||window.webkitAudioContext)();
    const o = AC.createOscillator(), g = AC.createGain();
    o.type='square'; o.frequency.value = 900;
    g.gain.setValueAtTime(0.15, AC.currentTime);
    g.gain.exponentialRampToValueAtTime(0.0001, AC.currentTime+0.05);
    o.connect(g).connect(AC.destination); o.start(); o.stop(AC.currentTime+0.06);
  }catch(e){}
}
```

Важно для iOS: `AudioContext` должен быть создан/возобновлён по жесту пользователя. Поэтому вызываем `AC.resume()` при нажатии «Start Quiz». Также нужна настройка «звук вкл/выкл» в кабинете.

### 2.2. Калькулятор и холст

- Подключить существующий код из reader (найти в `reader.html`/общем JS). Желательно вынести в общий модуль `tools.js`, чтобы не дублировать код (но только после того, как quiz заработает с копией — иначе риск сломать reader).

- **Таймер не останавливается:** он живёт в корневом состоянии и не зависит от открытых панелей. Критерий: при открытии калькулятора на 30 секунд `elapsedMs` вырастает на ~30 000 ± 300.
- Холст: сохранять рисунок **на вопрос** (`Map<questionId, ImageData/dataURL>`), чтобы при переходе назад-вперёд черновик не терялся. Очищать при завершении сессии.
- Для холста на iOS: `touch-action:none` на canvas, иначе страница будет скроллиться при рисовании. Использовать Pointer Events и `devicePixelRatio`.
- Нужно проверить, что калькулятор не перехватывает горячие клавиши, которые использует квиз (1–4, Enter, стрелки).

### 2.3. Пропуск вопроса

Рекомендую **колоду карт** (вариант 2 из ваших). Он проще пулa, естественно интегрируется с навигацией и гарантирует возврат.

```js
function skip(){
  const id = S.deck[S.idx];
  S.skipped.add(id);
  S.deck.splice(S.idx, 1);   // убрать с текущей позиции
  S.deck.push(id);           // в конец
  // idx не увеличиваем: на его место встала следующая карточка
  if (S.idx >= S.deck.length) S.idx = S.deck.length-1;
  render(); toast(t('skipped'));
}
// завершение: сессия закончена, только когда у ВСЕХ id есть answers[id].choice
const done = () => S.deck.every(id => S.answers[id]?.choice != null);
```

Нужно продумать крайние случаи:

- Если остались только пропущенные вопросы, то пропуск последнего вопроса переставляет его на ту же позицию. Нужно сообщение «Остался один вопрос, пропустить нельзя» или разрешить бесконечный пропуск, но блокировать завершение. Рекомендую первое.
- Индикатор: счётчик «пропущено: N» + цветная метка на карточках в навигаторе.
- Счётчик «1 / N»: показывать **отвеченные/всего**, а не позицию (иначе после пропуска всё путается).
- Результаты: время на вопрос считать **суммарно** по всем показам одного вопроса.
- Метрика «сколько раз пропущен» полезна для слабых мест, так что `skippedCount` стоит писать в статистику.
- Если пользователь нажимает «Завершить досрочно» с пропущенными, то спросить: засчитать их как неверные? (рекомендую: да, и показать это в обзоре).

### 2.4. CD-навигация по вопросам

Компактная полоса управления (одна строка, высота ~40px):

```
⏮  ◀  [ 7 / 40 ▾ ]  ▶  ⏭
```

- ⏮ — к первому, ◀ — назад, ▶ — вперёд, ⏭ — к последнему.
- Центральная кнопка с номером открывает «выбор трека»: сетка номеров (1…N), цвета по статусу: серый (не отвечен), зелёный (верно), красный (неверно), жёлтый (пропущен), синий (текущий). В режиме «Exam Sim» цвета верно/неверно скрыты, показываем только «отвечен/нет».

- **Важная бизнес-логика:** уже отвеченный вопрос при возврате показывается в режиме просмотра (ответ зафиксирован, показан результат), если не включён режим «можно менять ответ». Это нужно решить с вами.

Это обязательный тест: чтобы пользователь, у которого раньше было сохранено в `localStorage` старое значение, тоже получил пустой выбор (нужна версия схемы `quizPrefsV2`).

### 2.6. Экран квиза: эффективность пространства

Цель: ≥90% площади под информацию (вопрос, варианты, объяснение).

- Вся служебная часть в одной верхней строке: `✕ | 7/40 | ⏱ 12:30 | 🧮 ✏️ | ⏭ пропуск`, 40–44px.
- Нижняя панель только для навигации и «Next» (одна строка, 48px, с учётом `env(safe-area-inset-bottom)`).
- Отступы: поля 8–10px на телефоне, 12–16px на десктопе. Использовать `clamp()`.
- Использовать `100dvh`, а не `100vh` (иначе на iOS Safari панель адреса «съедает» нижние кнопки).
- Скрыть общую навигацию (7 ссылок) на экране квиза во время сессии (она нужна только в лобби).
- Сделать оценку «Difficult / Easy» компактной (две маленькие иконки), и показывать её после ответа.
- Варианты ответов: крупная нажимаемая область (мин. 44×44), но плотный межстрочный интервал.
- На широких экранах: двухколоночный режим (вопрос слева, объяснение/холст/калькулятор справа) вместо растягивания на всю ширину.

```css
:root{
  --pad:clamp(8px,1.6vw,16px);
```

## 4. Этапы

1. **Фаза 0. Аудит и «заморозка».** Снимок inventory, скриншоты 5 размеров, список строк для i18n, список localStorage-ключей. Критерий: документ утверждён.
2. **Фаза 1. i18n и язык.** Один переключатель, словарь, автотест утечки языка. Всё остальное пока без изменений.
3. **Фаза 2. Лобби (компактность, пустые дисциплины, свёрнутый радар, пресеты).**
4. **Фаза 3. Каркас экрана квиза (экономия места) без новых функций.**
5. **Фаза 4. Таймер** (логика, затем визуал, затем звук).
6. **Фаза 5. Пропуск + навигация.**
7. **Фаза 6. Калькулятор и холст.**
8. **Фаза 7. Полировка, доступность, производительность, PWA/кэш.**
9. **Фаза 8. Краш-тесты и приёмка.**

После каждой фазы запускается регрессия. Переход дальше только при зелёных тестах.

## 5. Критерии готовности (все обязательны; сомнение = доработка)

### A. Регрессия («ничего не сломали»)
- A1. Inventory-diff: ни один `id`/`onclick` не удалён без записи в журнале.
- A2. Все режимы (Quiz, Smart Drill, Weak Spots, Exam Sim, All Questions List) запускаются и завершаются; результаты, EXP, rank, история сессий, избранное, плейлисты, жалобы (Report Issue), «Open in Reader», кабинет, вход/выход, админ-панель работают как раньше.
- A3. Статистика после сессии идентична ожидаемой (сравнить на контрольной сессии до/после правок: точность, EXP, время).
- A4. Старые данные пользователя (localStorage/облако) открываются без потерь.

### B. Язык
- B1. Автотест утечки языка проходит в EN и RU на **каждом** экране: лобби, квиз, результаты, кабинет, все модалки, тосты, подтверждения, ошибки.
- B2. Один переключатель, мгновенный эффект без перезагрузки, выбор сохраняется.
- B3. Нет ни одного `[i18n miss]` в консоли за полный прогон.
- B4. Тексты в обоих языках влезают в кнопки (RU обычно на 20–30% длиннее): нет обрезаний и переносов, ломающих вёрстку.

### C. Таймер
- C1. Юнит-тест `phaseOf` на границах для лимитов 10, 20, 40, 50, 250: ровно 70/90/100% и ±1 сек.
- C2. Старт сразу при запуске квиза; формат `0:00`, `16:45`, `100:05` (>60 мин без часов).
- C3. Пауза/возобновление по тапу; в паузе время не идёт (проверка: пауза 60 сек, потеря ≤ 0.5 сек).
- C4. Лимит = N × 60 сек для всех пресетов, включая «ALL» (N = фактическое число вопросов).
- C5. Смена фазы даёт один щелчок (ровно один на переход, не повторяется при перерисовке; не звучит при восстановлении сессии).
- C6. Таймер переживает: открытие калькулятора/холста, сворачивание вкладки на 2 минуты, поворот экрана, пропуск вопросов, навигацию.
- C7. Дрейф: за 10 минут разница с эталонным временем ≤ 1 сек.
- C8. Эффекты (цветы/листья/капли/мухи) не роняют FPS ниже 50 на среднем телефоне; `prefers-reduced-motion` их отключает.

### D. Пропуск и навигация
- D1. Пропущенный вопрос гарантированно возвращается; сессию нельзя завершить, пока есть неотвеченные.
- D2. Пропуск последнего оставшегося вопроса обрабатывается без зависания и пустого экрана.
- D3. Многократные пропуски одного вопроса, 100 пропусков подряд, пропуск всех вопросов, затем ответ на все: итог корректен.
- D4. ⏮ ◀ ▶ ⏭ и выбор номера работают на крайних значениях (1 и N), цвета статусов верны.
- D5. Ответ, данный до пропуска/возврата, не теряется и не удваивается в статистике.

### E. Инструменты
- E1. Калькулятор и холст открываются из квиза, считают/рисуют так же, как в reader.
- E2. Рисунок привязан к вопросу, не пропадает при навигации.
- E3. На iOS Safari при рисовании страница не скроллится.

### F. Компактность и адаптивность
- F1. Снимки на ширинах 320, 360, 390, 414, 768, 820, 1024, 1280, 1440, 1920, а также в ландшафте: нет горизонтального скролла, нет обрезанных кнопок, нет перекрытий.
- F2. Замер: площадь, занятая вопросом, вариантами и объяснением, ≥ 90% высоты экрана без учёта верхней и нижней панелей по 44–48px (автоматически: сумма `getBoundingClientRect` информационных блоков / `innerHeight`).
- F3. В лобби кнопка «Start» видна **без прокрутки** на экране 360×640.
- F4. Все интерактивные элементы ≥ 44×44 px (автопроверка).
- F5. Safe areas (чёлка, home indicator) не перекрывают контент.
- F6. Светлая и тёмная темы читаемы (контраст ≥ 4.5:1).

### G. Лобби
- G1. Радар свёрнут при первом открытии, состояние запоминается, разворачивание/сворачивание плавное.
- G2. Дисциплины по умолчанию пусто даже у существующих пользователей; «Start» без выбора заблокирован с понятным пояснением.
- G3. Пресеты в одной кнопке; выбор работает, значение сохраняется.
- G4. Источник (сборники/дисциплины) выбирается одним контролом, выбор из обоих режимов не конфликтует.

### H. Краш-тесты
- H1. Закрыть вкладку посреди сессии, открыть снова: сессия восстанавливается (время, ответы, пропуски).
- H2. Нет сети (офлайн PWA): квиз стартует из кэша и завершается; результат сохраняется и синхронизируется потом.
- H3. Заполненное `localStorage` (квота), повреждённый JSON в хранилище: приложение стартует, не падает.
- H4. Очень быстрые нажатия (50 тапов за 2 сек по Next/Skip/Pause): нет двойных переходов и рассинхронов.
- H5. Пустые/повреждённые манифесты, вопросов меньше, чем в пресете (например, пресет 250, а в теме 12): корректная работа и лимит времени пересчитан по фактическому числу.
- H6. Смена языка посреди сессии: интерфейс переключается, состояние и таймер не сбрасываются.
- H7. Длительная сессия (300 вопросов, 2+ часа): память стабильна, таймер не дрейфует, UI не лагает.
- H8. Поворот экрана и изменение размера окна на десктопе во время сессии.
- H9. Браузеры: iOS Safari (последние 2 версии), Chrome Android, Chrome/Edge/Firefox/Safari desktop, установленный PWA.
- H10. Консоль чистая: ноль необработанных ошибок за полный прогон.

### I. Решение критика и оркестратора
- I1. У критика не осталось блокирующих замечаний.
- I2. Каждый пункт A–H зафиксирован в протоколе как «пройден» с датой и конфигурацией.
- I3. Любой «сомнительный» результат = возврат на доработку, и после правки перепроходятся пункты этой группы и вся группа A.

## 6. Инструменты тестирования

- **Playwright** с проектами для устройств (`iPhone 13`, `Pixel 7`, `iPad`, desktop) и скриншот-сравнением.
- Для таймера используйте `page.clock` (быстрая перемотка времени): тест 40-минутной сессии за секунды, с проверкой смены фаз на 1680/2160/2400 сек.
- Ручной прогон на реальном iPhone и Android минимум один полный цикл (аудио, холст, safe areas на реальном железе не воспроизводятся полностью в эмуляторе).

```js
// пример: границы фаз
test('phases for 40q', async ({page}) => {
  await page.clock.install(); await startQuiz(page, 40);
  for (const [sec, ph] of [[1680,0],[1681,1],[2160,1],[2161,2],[2400,2],[2401,3]]) {
    await page.clock.fastForward(1000*(sec - (await elapsed(page))));
    expect(await page.locator('.tm').getAttribute('data-ph')).toBe(String(ph));
  }
});
```
